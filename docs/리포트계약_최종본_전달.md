# 리포트 계약 최종본 전달

리포트 계약서는 AI 레포 `docs/리포트생성_API계약_백엔드전달용.md`입니다.
**이게 최종본이고, 이 문서로 엔티티와 파싱 코드를 만드셔도 됩니다.**

9/3에 드리기로 했는데 전달이 늦었습니다. 백엔드 `docs/13-report.md`의
「계약 도착 시 확인할 것」 8개 항목에 대한 답을 먼저 정리하고,
그 뒤에 계약서에서 꼭 보셔야 할 부분을 모았습니다.

---

## 확인하실 8개 항목

| # | 질문 | 답 |
| --- | --- | --- |
| 1 | 점수 스케일 | 모든 점수 0~100 정수. 화면용 1~5 등급(`display`)이 같이 옴 |
| 2 | 작업 등록 · 폴링이 질문 생성과 같은가 | 같음. 202 + `task_id` → `GET /ai/tasks/{task_id}` |
| 3 | 소요 시간 | 9문항 약 5분. 폴링 타임아웃 10분 권장 |
| 4 | 진행률 `stage` 값 | 5개. 그리고 `progress`(0~1)가 같이 옴 |
| 5 | 부분 실패 표현 | 축마다 `status`. `overall.partial` · `axes_failed` |
| 6 | 실패한 축만 재시도 | 가능. `POST .../report/retry` |
| 7 | 회차 비교 | **AI가 계산해서 줌.** 백엔드는 리포트 원본을 모아 보내기만 |
| 8 | 결과 JSON 전체 스키마 | 계약서 4장 |

### 1. 점수 스케일

```
score     0~100 정수. 총점 · 축 점수 · 문항 점수 전부 같은 자
display   1~5 정수. 화면에 별점이나 등급으로 쓸 값
```

| display | score |
| --- | --- |
| 5 | 85~100 |
| 4 | 70~84 |
| 3 | 50~69 |
| 2 | 30~49 |
| 1 | 0~29 |

축마다 스케일이 다르지 않습니다. 세 축 모두 0~100입니다.

### 2. 작업 등록 · 폴링

질문 생성과 같은 구조라 `AiPoller`를 그대로 쓰실 수 있습니다. 차이는 세 가지입니다.

| | 질문 생성 | 리포트 |
| --- | --- | --- |
| 멱등성 키 | 없음 | **`Idempotency-Key` 헤더 필수** |
| 같은 요청 재전송 | 새 `task_id` | **같은 키면 기존 `task_id` 반환** |
| 진행률 | `stage`만 | `stage` + `progress` |

`Idempotency-Key`는 `rpt_{session_id}_{시도번호}` 형식을 권장합니다.
사용자가 재분석을 누를 때만 시도번호를 올리시면 됩니다.

### 3. 소요 시간

```
전사          거의 0초   세션 중 이미 해 둔 결과를 재사용
시선 분석     약 4분     9문항 기준, GPU
내용 채점     수십 초    문항마다 Claude 호출
조립          1초 미만
───────────────────────
합계          약 5분
```

**폴링 타임아웃은 10분으로 잡아 주세요.** 질문 생성(90초 · 60초)과 다른 값입니다.
영상을 안 쓰는 세션(`video_url`이 전부 null)은 1분 안쪽입니다.

### 4. 진행률

```json
{ "status": "processing", "stage": "analyzing_gaze", "progress": 0.6 }
```

| stage | 의미 |
| --- | --- |
| `transcribing` | 음성 인식 |
| `analyzing_speech` | 말하기 분석 |
| `analyzing_gaze` | 시선 분석. 가장 오래 걸림 |
| `analyzing_content` | 내용 채점 |
| `composing` | 리포트 조립 |

질문 생성과 마찬가지로 이 값을 프론트에 그대로 내보내지 말고 백엔드 enum으로 매핑해 주세요.
`progress`는 WebSocket 진행 표시에 바로 쓰시면 됩니다.

### 5. 부분 실패

**`13-report.md`에 적어 두신 규칙과 같습니다.**

| 축 | 실패하면 | 응답 |
| --- | --- | --- |
| 내용 | 전체 실패 | `status: error`, `error_code: CONTENT_FAILED`. `result` 없음 |
| 말하기 | 해당 축만 | `status: done`, `axes.speech.status: failed` |
| 시선 | 해당 축만 | `status: done`, `axes.gaze.status: failed` |

부분 실패일 때 리포트에 이렇게 표시됩니다.

```json
"report_status": "partial",
"overall": {
  "partial": true,
  "axes_used": ["content", "speech"],
  "axes_failed": ["gaze"]
}
```

**`failed`와 `skipped`는 다릅니다.** 카메라를 끄고 면접하면(`video_url`이 전부 null)
시선 축이 `skipped`로 옵니다. 실패가 아니라 정상입니다. 화면에서는
`failed`는 「분석 실패」, `skipped`는 「카메라 미사용」으로 구분해 주세요.

실패한 축이 빠지면 남은 축으로 가중치를 나눠 총점을 다시 냅니다. 계약서 6장에 표가 있습니다.

### 6. 실패한 축만 재시도

```
POST /ai/sessions/{session_id}/report/retry
{ "axes": ["gaze"], "answers": [ ... ] }
```

요청한 축만 계산해서 돌려줍니다. 성공한 축은 다시 계산하지 않습니다.
받은 결과를 기존 리포트에 **병합**해 주세요. 전사는 캐시에서 나와서 빠릅니다.

### 7. 회차 비교 — AI가 계산합니다

```
POST /ai/reports/compare
{ "reports": [ { "session_id": "...", "round": 1, "report": { 리포트 원본 } }, ... ] }
```

**`growth` 모듈이 작아집니다.** 백엔드는 해당 사용자의 회차별 리포트 원본을
순서대로 모아서 보내기만 하면 됩니다. AI가 돌려주는 것은 이렇습니다.

| 필드 | 내용 |
| --- | --- |
| `vs_previous` | 직전 회차 대비 총점 · 축별 변화, 오른 문항 · 떨어진 문항, 코멘트 |
| `trend` | 전체 회차의 총점 · 축별 점수 배열. 꺾은선 그래프에 바로 쓸 수 있음 |
| `trend.stalled_axes` | 최근 3회차 동안 정체된 축 |
| `by_question` | 문항별 회차 점수 배열과 변화량 |

**비교 요청은 즉시 응답합니다.** 폴링이 필요 없습니다.

회차 수 제한은 없습니다. AI는 리포트를 저장하지 않으므로 **리포트 JSON 원본을 삭제하지
말고 보관**해 주세요. 비교할 때마다 전체 회차를 함께 보내야 합니다.

비교 대상은 `is_replay: true`인 문항뿐입니다. `12-replay.md`에 적어 두신 것과 같습니다.

### 8. 전체 스키마

계약서 4장에 전체 JSON 예시와 필드 규칙이 있습니다. 큰 틀은 이렇습니다.

```
result
├─ session_id, generated_at, report_status (complete | partial)
├─ overall        총점, 등급, 게이트 여부, 부분 실패 여부
├─ axes
│  ├─ content     status, score, display, metrics, evidence[]
│  ├─ speech      (같음)
│  └─ gaze        (같음)
├─ questions[]    문항별 점수 · 축 점수 · 전사 · 길이 · 시간초과 · 되묻기 여부
├─ resilience     압박 대응력. 친절형이면 null
├─ company_comment 기업 인재상 코멘트. 기업 미선택이면 null
└─ improved_answers[] 개선 답변 제안
```

엔티티는 **리포트 JSON 원본을 통째로 저장하는 컬럼 하나**와, 목록 화면에 필요한
몇 개(`overall.score`, `report_status`, `generated_at`)만 따로 두시는 것을 권합니다.
회차 비교 때 원본을 그대로 보내야 해서, 쪼개서 저장하면 다시 조립해야 합니다.

## 계약서에서 꼭 보셔야 할 것

### 요청에 `is_replay` · `is_spare_topic`을 실어 주세요

AI는 세션을 보관하지 않아서, 요청으로 받지 않으면 이 두 값을 알 수 없습니다.
**보내지 않으면 회차 비교의 `by_question`이 항상 빈 배열이 됩니다.**
면접 중에 이미 저장하고 계신 값을 그대로 넣으시면 됩니다.

### 되묻기 답변도 같이 보내 주세요

되묻기(`type: reask`)는 독립 문항으로 점수를 내지 않고, `reask_of`가 가리키는 원 질문에
이어 붙여 하나로 채점합니다. `answers`에 세션에서 실제로 나간 질문 전부를 순서대로 담아 주세요.

### 적절성 게이트

질문에 답하지 않은 답변이 말하기 · 시선 점수로 높은 총점을 받는 것을 막는 장치입니다.

| 내용 점수 | 총점 상한 |
| --- | --- |
| 0~29 | 40 |
| 30~49 | 70 |
| 50 이상 | 없음 |

걸리면 `overall.gated: true`, `overall.gate_reason: "content_relevance_low"`가 옵니다.
화면에서 「답변이 질문과 맞지 않아 총점이 제한되었습니다」 같은 안내를 띄우시면 됩니다.

### 기업 인재상은 `company_profile_override`로 보내 주세요

`10-ai-client.md`에 정해 두신 대로, 선택된 기업의 인재상을 `company_profile_override`에
문자열로 담아 보내 주세요. 질문 생성 때와 같은 방식입니다. 기업 코멘트가 그 인재상을 보고 만들어집니다.

`company_id`는 기록용으로 백엔드 PK를 그대로 보내시면 됩니다.
AI 쪽에 아직 `company_id`로 자체 목록을 찾는 코드와 `GET /ai/companies`가 남아 있는데,
백엔드 결정에 맞춰 1단계 안에 정리하겠습니다. 백엔드가 바꾸실 것은 없습니다.

### 에러는 대부분 폴링 응답으로 옵니다

| 코드 | 어디서 | 재시도 |
| --- | --- | --- |
| `INVALID_REQUEST` · `INVALID_ANSWERS` | 요청 즉시 400 | 없음 |
| `REPORT_TOO_SHORT` | 요청 즉시 422 | 없음. 2문항 미만이면 리포트를 만들지 않음 |
| `CONTENT_FAILED` | 폴링 `status: error` | 1회 |
| `STT_FAILED` | 폴링 `status: error` | 없음 |
| `MEDIA_FETCH_FAILED` | 폴링 `status: error` | 1회. 새 presigned URL로 |

### presigned URL 만료

| 용도 | 만료 |
| --- | --- |
| 이력서 | 15분 (지금 설정 그대로) |
| **답변 영상 · 음성 (리포트용)** | **30분 이상** |

리포트는 영상을 내려받아 분석하는 데 몇 분이 걸립니다. 만료가 짧으면
분석 도중 `MEDIA_FETCH_FAILED`가 납니다.

## 지금 더미가 주는 값

더미 서버로 붙이시면 구조는 실제와 같지만 값은 가짜입니다.
**테스트용 트리거**를 `audio_url` · `video_url`에 넣으면 각 상황을 재현할 수 있습니다.

| 넣을 문자열 | 어디에 | 결과 |
| --- | --- | --- |
| `fail` | `video_url` | 시선 축만 실패 → 부분 리포트 |
| `fail` | `audio_url` | 말하기 축만 실패 → 부분 리포트 |
| `content_fail` | `audio_url` | 전체 실패 → `CONTENT_FAILED` |
| `offtopic` | `audio_url` | 내용 10~29점 → 총점 상한 40 |
| `partial` | `audio_url` | 내용 30~49점 → 총점 상한 70 |

`video_url`을 전부 null로 보내면 시선 축이 `skipped`로 옵니다.

**실제 모드에서도 필드 구조는 바뀌지 않습니다.** 값만 진짜가 됩니다.
개선 답변 · 기업 코멘트 · 압박 대응력 · 회차 비교 코멘트는 지금 고정 문장이고,
10/4까지 실제 생성으로 바꿉니다.

## 아직 값이 바뀔 수 있는 것

**전부 값의 문제이고 구조는 바뀌지 않습니다.**

| 항목 | 상태 |
| --- | --- |
| 축 가중치 | **확정** — 내용 0.5 · 말하기 0.25 · 시선 0.25 |
| 말하기 `metrics` | **확정** — `hesitation_score` · `speech_rate_cv` · `repetition_count` |
| 내용 · 시선 `metrics` | 빈 객체. 키가 정해지면 추가만 됨 |
| 게이트 임계값 | 30 · 50. 검증 중이며 값만 바뀔 수 있음 |
| 압박 대응력 산출식 | 압박형 실제 세션을 모은 뒤 확정 |
