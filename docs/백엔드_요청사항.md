# AI 파트가 백엔드에 요청하는 것

「질문생성 API계약」 12장과 「리포트생성 API계약」 10장에 흩어져 있는 것을
한 곳에 모으고 우선순위를 붙였습니다.

**P0는 없으면 해당 기능을 아예 만들 수 없는 것입니다.**

---

## P0 — 지금 필요합니다

### 1. S3 버킷 + AI 업로드 권한 + 버킷 CORS

3주차에 TTS를 붙이면 AI가 mp3를 만들어 **S3에 직접 업로드하고 URL만 반환**합니다.
그래야 AI 서버 주소가 프론트에 노출되지 않고, mp3 바이너리를 API 응답에
실어 나르지 않아도 됩니다.

```
필요한 것
  버킷 이름과 경로 규칙
  AI 서버용 업로드 권한 (IAM 역할 또는 액세스 키)
  버킷 CORS 설정
```

**CORS는 반드시 설정해야 합니다.**

```
Access-Control-Allow-Origin: *
```

없으면 오디오는 재생되지만 **아바타 입이 움직이지 않습니다.**
프론트가 Web Audio API로 음량을 읽어야 하는데 CORS 헤더가 없으면 무음으로 읽힙니다.
로컬에서는 정상이다가 배포 후에만 실패하는 유형이라 미리 잡아야 합니다.

> 자격증명 제공이 어려우면 AI가 base64로 반환하고 백엔드가 업로드하는 방식으로
> 전환할 수 있습니다. 다만 폴링 응답이 질문당 100KB 이상으로 커집니다.

**3주차 시작 전까지 필요합니다.** 지금은 샘플 mp3 URL 하나를 고정 반환하고 있습니다.

### 2. 로그 테이블에 `answer_video_url` 추가

리포트의 **시선 축을 만들려면 답변 영상이 필요합니다.**
현재 답변 제출 계약이 `audio_url`만 받고 있어 영상 경로가 끊겨 있습니다.

```
answer_video_url   TEXT   NULL 허용 (카메라 미사용 시)
```

없으면 3축 중 하나를 통째로 못 만듭니다.

### 3. 리포트 요청 `answers[]`에 `is_replay` · `is_spare_topic`

`계약서_변경사항.md` 4번 참고. 로그 테이블에 이미 저장하는 값입니다.
**안 보내면 회차 비교가 동작하지 않습니다.**

### 4. presigned URL 만료 시간

```
이력서 파싱용   10분 이상
영상 분석용     30분 이상
```

파싱과 CV 처리가 태스크 안에서 이뤄지는데, 큐가 밀리면 발급 시점과 사용 시점 사이에
간격이 생깁니다. 영상은 다운로드 + CV 처리 시간까지 포함해야 합니다.

### 5. `replay_log` 꼬리질문에 `difficulty` 포함

재연습에서 1회차 구조를 재생하려면 꼬리질문의 난이도가 필요합니다.

```json
{ "type": "followup", "difficulty": "L2" }
```

`text`는 새로 생성하므로 필요 없습니다.

## P1 — 통합 전까지

### 6. 폴링 타임아웃

작업 종류마다 다릅니다. 단일 기준으로 잡으면 세션 시작에서 오탐이 납니다.

```
세션 시작   주질문 여러 개 + TTS   예상 10~30초   권장 타임아웃 90초
답변 처리   STT + LLM + TTS        예상 5~15초    권장 타임아웃 60초
리포트      영상 다운로드 + CV      훨씬 오래       권장 타임아웃 10분
```

**폴링 루프는 `DUMMY_POLL_TICKS=3`으로 띄워서 검증해 주세요.**
기본값에서는 즉시 `done`이라 `processing` 분기가 실행되지 않습니다.
`processing`과 `error` 응답에는 `result`가 없으니 `status`를 먼저 보고 분기하시면 됩니다.

### 7. 로그 테이블 PK는 `(session_id, question_id)` 복합키

`question_id`가 `"q_1"`, `"q_4r"` 형태라 **세션 안에서만 유일합니다.**
단일 PK로 두면 다른 세션과 충돌합니다.

### 8. `reask_of` 저장

되묻기 답변은 원 질문의 답변에 이어 붙여 하나로 채점합니다.
어느 질문의 되묻기였는지 모르면 별도 문항으로 잘못 세게 됩니다.

**`q_4r` 형태의 접미사로 추측하지 말고 값으로 저장해 주세요.**

### 9. `is_replay` 저장

저장하지 않으면 회차 비교를 할 수 없습니다.
리포트를 나중에 다시 열었을 때 무엇이 비교 대상이었는지 알 수 없어집니다.

### 10. 리포트 JSON 원본 보관

**AI는 리포트를 저장하지 않습니다.**
회차 비교 요청에 전체 회차를 함께 보내야 하므로 오래된 회차도 삭제하지 마세요.

### 11. `Idempotency-Key` 발급 규칙 합의

```
권장 형식   rpt_{session_id}_{시도번호}
```

사용자가 재분석을 누르면 시도번호를 올립니다.
같은 키로 다시 요청하면 새 작업을 만들지 않고 기존 `task_id`를 반환합니다.

## 배포 관련 — 인프라 담당자와 함께

### 12. AI 서버 배포 주소

백엔드가 붙을 주소가 필요합니다. 내부망에 두고 외부에 노출하지 않습니다.

### 13. 공유 시크릿 실제 값

`CUEANDA_SHARED_SECRET` 환경변수입니다.
현재 더미는 설정하지 않으면 `dummy-secret`으로 뜨고 경고 로그를 남깁니다.

### 14. 인스턴스는 1개, 워커도 1개

**세션과 태스크를 프로세스 메모리에 들고 있습니다.**
워커나 레플리카를 늘리면 요청이 다른 프로세스로 갈 때마다 `SESSION_NOT_FOUND`가 납니다.

실제로 워커 2개로 같은 `task_id`를 10번 폴링했을 때 6번이 404였습니다.

```
gunicorn -w 4              ✗
K8s · ECS 레플리카 2개 이상   ✗
오토스케일링                ✗
```

**인스턴스를 늘리려면 Redis 같은 공유 저장소를 먼저 붙여야 합니다.**
인프라 담당자가 맡기로 되어 있어 지금은 붙이지 않았습니다.
언제 붙일지 일정만 알려주시면 맞추겠습니다.

### 15. 재배포 일정 공유

세션 상태가 임시 보관이라 재배포하면 진행 중이던 세션이 사라집니다.
`SESSION_NOT_FOUND`가 나는데 버그가 아닙니다.
개발 기간에는 재배포 전에 공유하겠습니다.

```
P0  answers[]에 is_replay · is_spare_topic  회차 비교에 필요
P0  presigned URL 만료 (이력서 10분 / 영상 30분)
P0  replay_log 꼬리질문에 difficulty

P1  폴링 타임아웃 90초 / 60초 / 10분
P1  (session_id, question_id) 복합키
P1  reask_of · is_replay 저장
P1  리포트 JSON 원본 보관
P1  Idempotency-Key 규칙 합의

배포  AI 서버 주소 · 시크릿 실제 값 · 인스턴스 1개 제약 · 재배포 일정
```
