# 노션 「인프라 관련 확인 질문」 답변 이후 바뀐 것

노션 「인프라 관련 확인 질문」에 AI가 답한 뒤로 바뀐 것만 모았습니다.
나머지 답은 그대로 유효합니다.

백엔드 `docs/90-open-questions.md`의 「AI 파트 회신 대기」 10개는 그 노션 페이지에서
답한 내용입니다. 목록에서 정리하셔도 됩니다.

---

## 바뀐 것

| 노션 답변 | 지금 | 백엔드 영향 |
| --- | --- | --- |
| RAG · FAISS 사용, 인덱스 볼륨 필요 | **쓰지 않음.** 자소서를 통째로 넣음. 볼륨 불필요 | 없음. 계약서 변경사항에서 알린 내용 |
| GPU는 확인 중 | **실제 모드는 학과 GPU 서버에서 AI만 따로 돌림** | 아래 「실제 모드」 참고 |
| `/ready` 응답 `{ "ready": true, "models": {...} }` | `{ "status": "ready", "mode": "dummy" }` | 없음. 지금 백엔드 코드는 `/ready`를 쓰지 않음 |
| 환경변수 목록 (`LLM_API_KEY`, `gpt-5-mini`, `WHISPER_*`, `FAISS_INDEX_DIR` 등) | LLM은 Claude로 바뀌었고 키 이름도 바뀜 | 없음. 아래 참고 |

**환경변수** — 노션 목록은 옛 것입니다. 백엔드 `.env.example`에 넣지 않으셨으니 그대로
두시면 됩니다. AI 서버 변수는 AI가 관리하고, 백엔드와 맞춰야 할 것은 하나뿐입니다.

```
CUEANDA_SHARED_SECRET   백엔드 APP_AI_SECRET과 같은 값
```

**넣지 않으면 AI는 기본값 `dummy-secret`으로 떠서 모든 요청이 401**입니다.

## 더미 서버를 붙이실 때

`dev` 브랜치의 `RealAiClient` · DTO가 보내는 요청 모양 그대로(snake_case, null 필드 생략)
더미 서버에 보내 봤습니다. 세션 시작 → 답변 6개 → 종료 → 재연습 → 중단 → 헬스체크까지
통과했고, 응답 필드와 DTO 필드가 어긋나는 곳은 없었습니다.

compose 예시입니다. 구성은 편하신 대로 바꾸셔도 됩니다.

```yaml
python-ai:
  build:
    context: ../AI            # AI 레포를 클론한 경로
    target: dummy
  environment:
    CUEANDA_SHARED_SECRET: ${APP_AI_SECRET:-local-dev-only-ai-secret}
  ports:
    - "8000:8000"
```

알아 두시면 좋은 것 두 가지입니다.

- **질문 음성(`audio_url`)은 null로 나갑니다.** 전에 주던 샘플 주소가 404라서 바꿨습니다.
  프론트는 null이면 텍스트로 넘어가게 돼 있습니다.
- **더미의 테스트 트리거는 URL 문자열로 동작합니다.** `audio_url`에 `short`가 있으면 되묻기,
  `fail`이 있으면 해당 축 실패 같은 식입니다. 실제 업로드 경로(`sessions/.../answers/q_1.webm`)에는
  이 글자가 없어서, 백엔드 흐름으로 붙이면 되묻기나 실패는 나오지 않습니다.
  그 화면을 확인하실 때는 URL에 글자를 넣어 AI를 직접 호출해 주세요. 목록은 AI 레포 `README.md`에 있습니다.

## 실제 모드 — 학과 서버에서 AI를 돌리면서 생기는 것

실제 모드는 GPU가 필요해서 **AI 서버만 학과 GPU 서버에서 돌립니다.**
노트북에서 SSH 터널로 연결할 예정입니다. 더미 연결에는 영향이 없습니다.

### 1. AI 서버 주소 — 알려 드리는 것

노션에서 「AI 주소를 환경변수로 받을 수 있는지」 여쭤본 게 이 경우입니다.
`APP_AI_BASE_URL`로 이미 받게 돼 있어서 값만 바꾸면 됩니다.
SSH 터널 기준으로 노트북에서는 `localhost:8000`에 AI 서버가 있는 것처럼 보입니다.
Spring을 컨테이너로 띄우시면 컨테이너 안에서는 `localhost`가 달라지니 참고해 주세요.

### 2. 녹화 파일 위치 — 알려 드리는 것

AI는 답변 음성 · 영상을 presigned URL로 내려받습니다. 노트북 안의 MinIO 주소는
학과 서버에서 닿지 않습니다. `20-storage.md`에 배포는 S3로 설계해 두셔서,
그 설정으로 가시면 될 것 같습니다.

### 3. 질문 음성 — 같이 정해야 합니다

**경로** — AI 코드를 맞추겠습니다. 백엔드에서 바꾸실 것은 없습니다.

| | 백엔드 설계 (`20-storage.md`) | AI 코드 지금 |
| --- | --- | --- |
| 경로 | `sessions/{sessionId}/questions/{questionId}.mp3` | `tts/{랜덤}.mp3` |
| AI 쓰기 권한 | `sessions/*/questions/*`에만 | 버킷 전체라고 가정 |

**재생 방식** — 정해 주셔야 합니다.

노션에서 말씀드린 대로 AI는 S3에 올린 파일의 주소를 `audio_url`로 돌려줍니다. 이 주소는
서명 없는 일반 주소입니다. 지금 백엔드 코드(`InterviewSessionWriter` → `InterviewAnswerPoller`)는
이 값을 그대로 저장해 프론트에 넘기는데, 버킷이 비공개면 프론트가 재생할 때 403이 납니다.

| | 방법 | 백엔드 | AI |
| --- | --- | --- | --- |
| A | `audio_url`에서 object key를 떼어 저장하고, 프론트에 줄 때 presigned GET으로 발급 | 작업 있음 | 없음 |
| B | `sessions/*/questions/*`만 공개 읽기 | 버킷 정책 | 없음 |

녹음 파일과 같은 원칙(key 저장 후 재발급)인 A가 맞아 보입니다.
질문 음성은 이력서 내용이 섞인 질문을 읽은 것이라 공개로 두는 건 권하지 않습니다.
어느 쪽이든 AI 쪽 작업은 없고, 결정만 알려 주시면 됩니다.

**그리고 실제 모드에서 쓸 버킷 이름과 AI용 쓰기 권한(키)을 받아야 합니다.**
AI가 질문 음성을 올릴 때 필요합니다.

## 노션 「추가로 알려드릴 것」 — 반영 확인

| 노션에서 요청 | 백엔드 `dev` |
| --- | --- |
| 답변 영상 경로 (`answer_video_url`) | ✅ `answer_video_object_key`로 저장, 답변 제출 때 `video_url` 전달 |
| presigned 만료 — 자소서 10분 이상 | ✅ 15분 |
| presigned 만료 — 영상 분석 30분 이상 | ✅ 녹음 다운로드 1시간 |
| AI 주소를 환경변수로 | ✅ `APP_AI_BASE_URL` |
| 버킷 CORS | ✅ 프론트 도메인 한정. AI 쪽도 이걸로 충분합니다 |

**Redis 공유**는 노션 답변 그대로입니다. 공유하시면 AI는 1번 DB를 씁니다.
AI 쪽 Redis는 선택이라, 붙이지 않으면 AI 프로세스 메모리로 돕니다.
