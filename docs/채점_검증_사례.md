## GPT 오류 유형별 분석

### 유형 A — 1점 → 2점 오류 (4건)

"AI 분야 내용이면 질문과 연관 있다"고 판단해 1점 답변을 2점으로 올림.

| 질문 | 답변 내용 | 정답 | GPT 판정 |
|------|---------|------|---------|
| Q3 과적합 방지 | "간단한 모델부터 시작하는 게 좋습니다" | **1점** | ~~2점~~ |
| Q5 RAG 경험 | "프롬프트 엔지니어링이 중요합니다" | **1점** | ~~2점~~ |
| Q6 양자화 경험 | "도메인 지식이 필요합니다" | **1점** | ~~2점~~ |
| Q8 스트리밍 운영 | "ML/데이터 엔지니어링 경계가 좁아지고 있습니다" | **1점** | ~~2점~~ |

→ **원인**: 체크 1에서 "AI 분야 내용 여부"로 판단. "특정 기술명 언급 여부"로 기준 강화 후 해결.

### 유형 B — 4점 → 5점 오류 (3건, 세트 1에서만 발생)

정량 수치(체크 3)가 있으면 4단계 완전성(체크 4)을 확인 않고 5점으로 올림.

| 질문 | 4점인 이유 (누락 단계) | GPT 판정 |
|------|-------------------|---------|
| Q1 NLP 모델 선택 | 배포 후 latency 측정 누락 | ~~5점~~ |
| Q2 데이터 불균형 | Precision 트레이드오프 분석 누락 | ~~5점~~ |
| Q3 과적합 방지 | 근본 원인 분석 단계 누락 | ~~5점~~ |

→ **원인**: 수치 확인(체크 3) 후 체크 4를 건너뜀.
→ **해결**: 프롬프트에 "수치가 있어도 체크 4로 반드시 이동할 것" 문장 추가.

## 점수별 대표 답변 예시

### 1점 — 유창하지만 주제이탈

체크 1 실패. 질문의 특정 기술명을 단 한 번도 언급하지 않음.

```
Q0 (CV/Diffusion 등급 기준?)
"제가 Computer Vision을 처음 접한 것은 2학년 때였습니다. 학회에서 논문 리뷰
세미나를 하는데, 이미지 한 장에서 이렇게 많은 정보를 뽑아낼 수 있다는 게
인상적이었습니다. 그때부터 관련 논문을 스무 편 정도 읽었고, 학회 발표도 여러 번
했습니다. 앞으로도 이 분야에서 계속 성장하고 싶다는 생각이 확고해졌습니다."
→ 체크 1 ✗ (등급 기준 언급 없음) → 즉시 1점 (15점)

Q5 (RAG 경험?)
"LLM을 활용할 때 프롬프트 엔지니어링이 가장 중요하다고 생각합니다.
Few-shot, Chain-of-Thought 같은 기법을 잘 활용하면 파인튜닝 없이도
좋은 성능을 낼 수 있습니다."
→ 체크 1 ✗ (RAG 언급 없음) → 즉시 1점 (13점)
```

### 2점 — 키워드 있음, 경험 없음

체크 1 통과, 체크 2 실패. 특정 기술명을 언급했으나 일반론·교과서 설명에 그침.

```
Q5 (RAG 경험?)
"RAG는 외부 지식을 검색해 LLM의 답변 품질을 높이는 기법입니다.
Vector DB로 검색한 관련 문서를 컨텍스트로 제공하면 Hallucination을 줄일 수 있습니다.
대표적인 도구로는 LangChain, LlamaIndex가 있습니다."
→ 체크 1 ✅ ("RAG" 언급) 체크 2 ✗ (본인 경험 없음) → 2점 (35점)

Q0 (CV/Diffusion 등급 기준?)
"경험 차이입니다. Computer Vision을 더 많이 다뤄봐서요."
→ 체크 1 ✅ ("경험 차이"라는 기준 언급) 체크 2 ✗ (구체적 경험 없음) → 2점 (35점)
```

### 3점 — 경험 있음, 수치 없음

체크 1·2 통과, 체크 3 실패. 직접 경험을 말하지만 정량 증거가 없음.

```
Q5 (RAG 경험?)
"RAG 시스템을 개인 프로젝트로 구현해봤습니다. LangChain과 ChromaDB를 사용했고
꽤 잘 작동했습니다. 정확한 평가는 하지 않았지만 기존보다 답변 품질이 좋아졌습니다."
→ 체크 1 ✅ 체크 2 ✅ 체크 3 ✗ (수치 없음) → 3점 (55점)
```

### 4점 — 수치 있음, 4단계 불완전

체크 1·2·3 통과, 체크 4 실패. 수치는 있지만 4단계 중 하나가 빠짐.

```
Q7 (A/B 테스트 경험?)
"추천 알고리즘 A/B 테스트에서 CTR이 3.2% → 4.1%로 향상됐습니다."
→ 체크 1 ✅ 체크 2 ✅ 체크 3 ✅ (CTR 수치)
→ 체크 4 ✗ (통계적 검정력 계산·실험 설계 단계 누락) → 4점 (77점)
```

### 5점 — 4단계 전 과정 완전

체크 1·2·3·4 모두 통과.

```
Q5 (RAG 경험?)
"사내 문서 검색에서 키워드 검색 Hit Rate 34%로 불만이 많았습니다(문제).
원인은 동의어·맥락 미반영(원인 분석).
LangChain + FAISS로 RAG 구축, text-embedding-ada-002 임베딩, Top-K=5 검색(해결).
Hit Rate 34% → 78%, 만족도 62% → 89%, 현재 프로덕션 운영 중(결과 측정)."
→ 체크 1~4 모두 ✅ → 5점 (94점)

Q6 (양자화 경험?)
"모바일 제약으로 모델 배포 불가(문제).
정확도 손실 최소화 목표(원인·목표 설정).
INT8 양자화 적용(해결).
98MB → 24MB, 300ms → 82ms, Accuracy -0.5%, Android 배포(결과 측정)."
→ 체크 1~4 모두 ✅ → 5점 (96점)
```

## 루브릭 설계 판단 근거

### 왜 4단계 순서가 이 순서인가

```
체크 1 (특정 기술명) → 체크 2 (직접 경험) → 체크 3 (정량 수치) → 체크 4 (4단계 전 과정)
```

- **체크 1이 첫 번째인 이유**: LLM이 주제이탈 답변에 높은 점수를 주는 가장 큰 원인.
  CV/Diffusion 앵커 답변이 1차 테스트에서 **88점**을 받은 것이 이 순서를 강제하게 된 직접 계기.
- **체크 2가 두 번째인 이유**: 기술명 아는 것(2점)과 실제로 써본 것(3점)은 면접에서 의미가 다름.
- **체크 3이 세 번째인 이유**: 수치가 있으면 과장이 어렵고, 실제로 측정했다는 증거.
- **체크 4가 마지막인 이유**: 가장 미묘한 경계. 수치도 있는 답변에서 구조적 완전성을 추가로 확인.

### 1점 기준을 "키워드"에서 "특정 기술명·방법명"으로 강화한 이유

초기: "핵심 키워드를 언급하지 않으면 1점"
문제: GPT가 "AI 분야 내용 = 어느 정도 연관 있음"으로 판단 → 1점 → 2점 오류 4건
수정: **질문에서 명시한 특정 기술명(RAG, 양자화 등)을 언급했는지**로 구체화
결과: 체크 1 관련 GPT 오류 패턴 명확히 차단

### 앵커 ④ (유창하지만 주제이탈)가 핵심인 이유

이 답변 유형이 **사람도, LLM도 속는 유형**입니다.
말은 유창하고 사례가 풍부하지만 질문이 요구한 것이 없습니다.
채점기가 여기에 30점 미만을 주지 못하면 적절성 게이트가 작동하지 않습니다.
1차 테스트에서 88점을 받은 것이 이 경계 강화의 직접 계기입니다.
