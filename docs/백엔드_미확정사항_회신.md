백엔드 `docs/90-open-questions.md`의 「AI 파트 회신 대기」 10개 항목에 대한 답입니다.
늦어서 죄송합니다. 대부분 AI 쪽에서는 정해져 있었는데 전달이 빠졌습니다.

**요약: 지금 바로 compose에 AI 컨테이너를 넣으실 수 있습니다.**

## 1 · 2 · 3. RAG와 벡터 저장소 — 쓰지 않습니다

자소서를 잘라서 검색하지 않고 통째로 LLM에 넣습니다. 자소서가 6페이지 안팎이라
검색할 이유가 없고, 통째로 넣어야 자소서와 프로젝트 이력을 엮어서 묻는 질문이 나옵니다.

**pgvector는 필요 없습니다.** `postgres:16` 그대로 쓰시면 됩니다.
질문 생성 계약의 `doc_id`는 RAG 인덱스가 아니라 파싱 캐시 키이며, 지금은 항상 null입니다.

## 4. AI 서버 Dockerfile — 있습니다

AI 레포 루트의 `Dockerfile`입니다. 단계가 둘로 나뉘어 있습니다.

| target | 용도 | GPU | 요금 |
| --- | --- | --- | --- |
| `dummy` | 통합 확인용. 질문 문장과 점수가 가짜, 구조는 실제와 동일 | 불필요 | 없음 |
| `full` | 실제 서비스. 전사 · 시선 분석 · Claude 호출 | 필요 | 세션당 약 130원 |

**compose 주석을 풀 때 이렇게 넣으시면 됩니다.**

```yaml
python-ai:
  build:
    context: ../AI            # AI 레포를 백엔드 레포 옆에 클론한 경로
    target: dummy
  container_name: cue-a-python-ai
  environment:
    CUEANDA_SHARED_SECRET: ${APP_AI_SECRET:-local-dev-only-ai-secret}
  ports:
    - "8000:8000"
  healthcheck:
    test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://localhost:8000/ready')"]
    interval: 5s
    timeout: 3s
    retries: 10
```

그리고 `spring` 서비스에서 두 가지를 바꿔 주세요.

```yaml
spring:
  depends_on:
    python-ai:
      condition: service_healthy
  environment:
    APP_AI_MOCK_ENABLED: ${APP_AI_MOCK_ENABLED:-false}   # true → false
```

`application-docker.yml`의 `http://python-ai:8000`은 그대로 맞습니다.

**연동 코드는 AI 쪽에서 미리 확인했습니다.** `dev` 브랜치의 `RealAiClient`와 DTO가
보내는 요청 모양 그대로(snake_case, null 필드 생략) 우리 서버에 보내 봤습니다.

```
세션 시작 → 답변 6개 → 종료 → 재연습 → 중단 → 헬스체크   전부 통과
응답 필드와 DTO 필드                                       어긋나는 것 0개
시크릿 헤더 X-Cueanda-Secret, 포트 8000                    일치
```

## 5. GPU — 실제 모드에서만 필요합니다

| 기능 | GPU | 비고 |
| --- | --- | --- |
| 전사 (Whisper) | 필요 | CPU로도 돌지만 답변 하나에 수십 초 |
| 시선 분석 (L2CS) | 필요 | 9문항에 약 4분 |
| 질문 생성 · 내용 채점 (Claude) | 불필요 | 외부 API |
| 음성 합성 (TTS) | 불필요 | 외부 API |

**더미 모드는 GPU가 전혀 필요 없습니다.** 지금 통합 확인에는 영향이 없습니다.

실제 모드는 이렇게 나누려고 합니다.

```
노트북     프론트 · 백엔드 · DB · Redis
학과 서버  AI 서버 (GPU)
AWS S3     녹화 파일 · 질문 음성
```

이 경우 **백엔드 파일 저장소를 MinIO에서 S3로 바꿔야 합니다.** 학과 서버가 노트북 안의
MinIO에 접근할 수 없어서입니다. `APP_STORAGE_ENDPOINT`만 바꾸면 되는 구조로 보이는데,
시점은 10/1 전후로 따로 말씀드리겠습니다. 자세한 일정은 `통합_일정.md` 2단계에 있습니다.

## 7. 헬스체크 — 두 개 있습니다

| 경로 | 의미 | 시크릿 헤더 |
| --- | --- | --- |
| `GET /health` | 프로세스가 살아 있는가 | 불필요 |
| `GET /ready` | 요청을 받을 준비가 되었는가 | 불필요 |

```json
{ "status": "ok", "mode": "dummy" }
{ "status": "ready", "mode": "dummy" }
```

compose의 healthcheck에는 `/ready`를 쓰시면 됩니다.
실제 모드에서는 모델 로딩이 끝나야 준비 완료가 됩니다.

## 8. 환경변수 — 더미는 하나입니다

| 변수 | 값 | 필수 |
| --- | --- | --- |
| `CUEANDA_SHARED_SECRET` | 백엔드 `APP_AI_SECRET`과 **같은 값** | 예 |

이름이 서로 다르니 compose에서 위 예시처럼 이어 주시면 됩니다.

실제 모드에서 늘어나는 변수는 AI 쪽에서 관리합니다. AI 서버가 학과 서버에서 따로 돌기
때문에 백엔드 `.env`에 넣으실 필요는 없습니다. 참고로 목록은 AI 레포 `.env.example`에 있습니다.

## 9. 더미 서버 — 지금 바로 쓰실 수 있습니다

`MockAiClient`로 먼저 진행해 두셔서 연결이 수월할 것 같습니다.
더미 서버가 목과 다른 점은 **세션 구성 로직이 실제로 돈다**는 것입니다.

```
실제와 같음   문항 수, 난이도 배분, 주제 구조, 되묻기, 예비 주제, 재연습
가짜         질문 문장, 점수, 음성 파일
```

`audio_url`에 `short`나 `insufficient`가 들어 있으면 부실한 답변으로 보고 되묻기가 나옵니다.
되묻기 흐름을 확인하실 때 쓰시면 됩니다. 다른 트리거는 AI 레포 `README.md`에 있습니다.

**질문 음성(`audio_url`)은 null로 바꿀 예정입니다.** 지금 더미가 주는 샘플 주소가
실제로는 없는 파일(404)이라서요. 계약상 null이면 텍스트만 띄우면 되므로 파싱은
그대로입니다.

## 10. S3 CORS를 프론트 도메인으로 한정 — 괜찮습니다

AI 서버는 presigned URL로 **서버에서** 파일을 내려받기 때문에 CORS의 영향을 받지 않습니다.

## 같이 확인 부탁드리는 것

질문 생성 계약에서 최근 정리한 부분입니다. 노션 댓글로도 답드린 내용입니다.

| 항목 | 내용 |
| --- | --- |
| `TTS_FAILED` | 응답으로 나가지 않습니다. `status: done`, `audio_url`만 null |
| `STT_FAILED` · `LLM_FAILED` | HTTP 500이 아니라 폴링 응답의 `status: error`로 나갑니다 |
| 재전송 | 폴링에서 error를 받은 뒤에만. processing 중에 또 보내면 문항이 하나 건너뜁니다 |
| 세션 시작 재시도 | 새 세션이 만들어집니다. 앞의 `session_id`는 버리시면 됩니다 |
| `doc_id` | 저장하지 않으셔도 됩니다 |
| 기업 인재상 | `10-ai-client.md`에 정하신 대로 `company_profile_override`로 보내 주세요. AI에 남은 `GET /ai/companies`와 `company_id` 조회는 AI 쪽에서 정리합니다 |

리포트 계약은 별도 문서 `리포트계약_최종본_전달.md`로 드립니다.
