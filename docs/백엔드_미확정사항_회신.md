# 백엔드 미확정 사항 회신

백엔드 `docs/90-open-questions.md`의 「AI 파트 회신 대기」 10개에 대한 답입니다.
늦어서 죄송합니다. 노션 최종 계약본과 댓글에서 정해진 내용이 대부분인데,
이 목록에는 따로 답을 드리지 못했습니다.

끝에 **AI 서버를 학과 서버에서 돌리면서 생기는 것** 세 가지를 덧붙였습니다.
그중 하나는 같이 정해야 합니다.

### 4. Dockerfile

단계가 둘입니다.

| target | 용도 | GPU | 요금 |
| --- | --- | --- | --- |
| `dummy` | 통합 확인용. 질문 문장 · 점수는 가짜, 구조는 실제와 같음 | 불필요 | 없음 |
| `full` | 실제 서비스 | 필요 | 세션당 약 130원 |

compose에 넣으실 때 참고용 예시입니다. 구성은 편하신 대로 바꾸셔도 됩니다.

```yaml
python-ai:
  build:
    context: ../AI            # AI 레포를 클론한 경로
    target: dummy
  environment:
    CUEANDA_SHARED_SECRET: ${APP_AI_SECRET:-local-dev-only-ai-secret}
  ports:
    - "8000:8000"
```

`dev` 브랜치의 `RealAiClient` · DTO가 보내는 요청 모양 그대로(snake_case, null 필드 생략)
더미 서버에 보내 봤습니다. 세션 시작 → 답변 6개 → 종료 → 재연습 → 중단 → 헬스체크까지
통과했고, 응답 필드와 DTO 필드가 어긋나는 곳은 없었습니다.

### 7. 헬스체크

```json
GET /health   { "status": "ok", "mode": "dummy" }
GET /ready    { "status": "ready", "mode": "dummy" }
```

실제 모드에서는 모델 로딩이 끝나야 `/ready`가 준비 완료가 됩니다.

### 8. 환경변수

`CUEANDA_SHARED_SECRET`에 백엔드 `APP_AI_SECRET`과 **같은 값**을 넣으면 됩니다.
이름이 서로 다릅니다. 실제 모드의 나머지 변수는 AI 쪽에서 관리합니다.

### 9. 더미 서버

목과 다른 점은 **세션 구성 로직이 실제로 돈다**는 것입니다.

```
실제와 같음   문항 수, 난이도 배분, 주제 구조, 되묻기, 예비 주제, 재연습
가짜         질문 문장, 점수
```

`audio_url`에 `short`가 들어 있으면 부실한 답변으로 보고 되묻기가 나옵니다.
다른 테스트 트리거는 AI 레포 `README.md`에 있습니다.

질문 음성(`audio_url`)은 곧 null로 바꿉니다. 지금 더미가 주는 샘플 주소가 404라서요.
프론트는 null이면 텍스트로 넘어가게 이미 돼 있습니다.

### 10. CORS

프론트가 질문 음성으로 아바타 입을 움직이는 기능은 프론트 도메인만 열어도 똑같이 됩니다.
AI 서버는 서버에서 파일을 내려받아서 CORS와 상관없습니다.

## AI 서버를 학과 서버에서 돌리면서 생기는 것

실제 모드는 GPU가 필요해서 **AI 서버만 학과 GPU 서버에서 돌립니다.**
노트북에서 SSH 터널로 연결할 예정입니다. 그래서 세 가지가 생깁니다.
시점은 10/1 전후입니다. 더미 연결에는 영향이 없습니다.

### 1. AI 서버 주소가 바뀝니다 — 알려 드리는 것

SSH 터널 기준으로 노트북에서는 `localhost:8000`에 AI 서버가 있는 것처럼 보입니다.
Spring을 컨테이너로 띄우시면 컨테이너 안에서는 `localhost`가 달라지니 참고해 주세요.

### 2. 녹화 파일이 학과 서버에서 닿는 곳에 있어야 합니다 — 알려 드리는 것

AI는 답변 음성 · 영상을 presigned URL로 내려받습니다. 노트북 안의 MinIO 주소는
학과 서버에서 닿지 않습니다. `20-storage.md`에 배포는 S3로 설계해 두셔서,
그 설정으로 가시면 될 것 같습니다.

### 3. 질문 음성 — 같이 정해야 합니다

`20-storage.md`와 AI 코드가 두 군데에서 다릅니다.

**경로** — AI 코드를 맞추겠습니다. 백엔드에서 바꾸실 것은 없습니다.

| | 백엔드 설계 | AI 코드 지금 |
| --- | --- | --- |
| 경로 | `sessions/{sessionId}/questions/{questionId}.mp3` | `tts/{랜덤}.mp3` |
| AI 쓰기 권한 | `sessions/*/questions/*`에만 | 버킷 전체라고 가정 |

**재생 방식** — 정해 주셔야 합니다.

AI는 업로드한 파일의 일반 S3 주소를 `audio_url`로 돌려줍니다.
버킷이 비공개면 프론트가 이 주소로 재생할 때 403이 납니다.

| | 방법 | 백엔드 | AI |
| --- | --- | --- | --- |
| A | `audio_url`에서 object key를 떼어 저장하고, 프론트에 줄 때 presigned GET으로 발급 | 작업 있음 | 없음 |
| B | `sessions/*/questions/*`만 공개 읽기 | 버킷 정책 | 없음 |

녹음 파일과 같은 원칙(key 저장 후 재발급)인 A가 맞아 보입니다.
질문 음성은 이력서 내용이 섞인 질문을 읽은 것이라 공개로 두는 건 권하지 않습니다.
어느 쪽이든 AI 쪽 작업은 없고, 결정만 알려 주시면 됩니다.

**그리고 실제 모드에서 쓸 버킷 이름과 AI용 쓰기 권한(키)을 받아야 합니다.**
AI가 질문 음성을 올릴 때 필요합니다.
